# 05 · 排查手册（Runbook）

> 线上问题的处理顺序永远一样：**先确认是不是真的坏了 → 再定位在哪一层 → 最后才动配置**。
> 顺序反了，就会在"明明服务正常"的情况下改坏一堆东西。

## 1. 三步定位

```
用户说"答得不对"
   │
   ├─ ① 服务还活着吗？        python -m ops.doctor --kb-id <id>
   │      连不上 → 看部署/网关/Token，别动检索参数
   │
   ├─ ② 资料召回了吗？        eval.runner --mode search
   │      召回空 → 查解析状态、分块内容、索引是否建完
   │      召回对 → 进 ③
   │
   └─ ③ 是生成的问题吗？      eval.runner --mode chat
          召回对但答错 → prompt / 模型 / 拒答策略
```

## 2. 常见故障速查

### 空召回

| 检查 | 命令 / 方法 | 判据 |
|---|---|---|
| 文档解析成功了吗 | `client.list_knowledge(kb_id)` 看状态 | 有 pending/processing 说明没解析完 |
| 分块内容还在吗 | `pipeline.ingest --dry-run --dump` 后搜原文片段 | 搜不到 = 清洗洗过头 |
| 用词是否对不上 | 换 2~3 个同义问法再试 | 只有某一种问法能召回 = 检索策略问题 |
| 索引是否重建 | 看最近一次入库时间 | 改了分块没重新入库 = 索引还是旧的 |

### 答非所问 / 混版本

- 同一个文档多个版本都在库里：`python -m pipeline.versioning --dir <目录>` 看冲突分级；
  入库用默认 `--version-policy latest` 只上当前有效版，旧版记录原因后跳过；
- 历史问题（"今年 1 月是什么标准"）：`--as-of 2026-01-01`，不要手工换库；
- **数值题答错**（"出差 9 天谁审批""二线城市住 5 晚报多少"）：先用
  `python -m pipeline.tables --dir <目录> --query "出差天数=9"` 看档位对不对。
  档位对、模型算错 → 改走结构化旁路，不要用 prompt 硬掰；档位不对 → 查表格是否被切碎；
- 条款被切断：看该块是否 `oversized=false` 且缺表头 → 回到分块规则；
- 引用指向错误文件：检查 `expected_source` 与文档 `title` 是否一致，标题不一致时引用匹配会失效。

### 入库被跳过 / 被阻断

| 现象 | 判据 | 处理 |
|---|---|---|
| 状态 `skipped`，原因"被 Vx.x 取代" | 同一文件编号有新版本 | 正常；确认新版已入库即可 |
| 状态 `skipped`，原因"尚未生效" | 生效日期在未来 | 等生效，或确认日期填错 |
| 状态 `blocked`，原因"密级高于知识库" | 文档密级 > `--kb-clearance` | 拆专用知识库 + 独立 Token，别调低门槛 |
| 状态 `blocked`，原因"文档体检 N 分" | 低于 `--min-quality` | 按体检建议补标题/拆表，退给文档 owner |
| 状态 `skipped`，原因"二进制文档" | docx/pdf 未加 `--allow-passthrough` | 确认密级后显式放行 |
| 状态 `failed` | 台账里有 `error` | 看错误是 4xx（参数）还是 5xx/超时（上游） |

### 慢

| 症状 | 可能原因 | 处理 |
|---|---|---|
| P50 正常、P95 很高 | 偶发重试、上游抖动 | 看 `last_retry_count`；减少并发 |
| 全部慢 | 模型服务排队 / 向量库挂载盘 IO | 先看上游自身指标，别调检索参数 |
| 入库慢 | 解析队列积压 | 看队列面板；分批入库 |

### 重复条目

- 症状：同一文档在知识库里出现两份，检索时重复占位；
- 原因：绕过 `upload_if_changed` 直接调用上传接口，或状态文件丢失；
- 处理：状态文件 `.weknora_state.json` 不要提交、也不要删；需要强制重传时，删掉对应条目
  （或改一个字节让内容指纹变化）再跑入库。

## 3. 变更规范（血泪版）

1. **改分块参数 = 全量重入库**，不要只对新增文档生效，否则库里两套规则并存，指标不可解释；
2. **改任何东西前后都跑离线基线与门禁**：`eval.offline --summary-json` + `eval.regression`，
   退化就退出码 1，别用"样本小"解释过去；
3. **改 prompt 前后各跑一次 chat 评测**，把 `eval/report/` 存成快照，用数字说话；
4. **不要在生产直接调参**：先在样例库上调，再全量；
5. 任何"临时注释掉一段逻辑"的改动，必须留下 TODO 和恢复条件；
6. 发布前跑 `python -m ops.release --dir <文档目录>`：体检/版本/密级/指标四道闸，
   有任何失败就不发；再跑 `python -m pipeline.ledger --require-ok` 确认上一批入库没有失败文件；
7. 每周把"没解决"的反馈导出，用 `python -m eval.badcase` 生成复核表，补全后入集——
   用例集不长大，门禁就是在守一份一年前的考卷。

## 4. 需要升级给上游的情况

- 解析器对某类文档稳定失败（加密 PDF、超宽表格）→ 提 issue 到 WeKnora，附脱敏样例；
- 检索接口返回结构变更 → 先看 `docs/swagger.yaml`，再改 `client/responses.py` 的兼容分支
  （评测与自检共用这一份口径，只改一处即可）；
- 模型侧回答质量整体下降（不是个别问题）→ 查模型服务版本、上下文长度截断。
